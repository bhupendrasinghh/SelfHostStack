How to Self-Host on a Cloud VPS: Zero-to-Production Blueprint

By Ashirwad Pratap Singh • October 7, 2026 • Target: how to self host on a vps | KD: 16 | Vol: 480/mo

What You'll Build: A fully secured Ubuntu 24.04 LTS VPS with SSH key authentication, UFW firewall, Docker Engine, an Nginx reverse proxy with Cloudflare Full (Strict) TLS 1.3, and your first self-hosted container running live under your custom domain.

Most beginner guides to self-hosting either stop at "SSH into your server and run a Docker command" or bury critical security steps in footnotes. This guide delivers the complete production architecture — including the networking, security, and DNS layers that cloud tutorials consistently omit.

Step 1: Provision Your Cloud VPS

Choose a VPS provider offering fast NVMe storage and a nearby datacenter. For a beginner homelab running 3–5 Docker containers, a 1 vCPU / 1–2 GB RAM / 25 GB SSD instance is sufficient. Recommended providers:

  • DigitalOcean Droplets — intuitive UI, $6/month for 1GB RAM
  • Hetzner Cloud — best value in EU, €4/month for 2GB RAM
  • Vultr — global datacenter presence, good India coverage
  • AWS Lightsail — AWS reliability with flat pricing at $5/month

Select Ubuntu 24.04 LTS as the operating system. During provisioning, paste your SSH public key (generated in Step 2) into the "SSH Keys" field.

Step 2: Generate a Secure SSH Ed25519 Key Pair

On your local machine (Windows PowerShell, macOS Terminal, or Linux bash):

ssh-keygen -t ed25519 -C "your-email@example.com" -f ~/.ssh/id_ed25519_vps

This generates two files:
~/.ssh/id_ed25519_vps — Private key (never share this)
~/.ssh/id_ed25519_vps.pub — Public key (paste this into your VPS provider)

Step 3: Initial Server Login & Non-Root User Setup

# Connect to VPS as root initially
ssh -i ~/.ssh/id_ed25519_vps root@YOUR_VPS_IP

# Create non-root admin user
adduser deploy_admin
usermod -aG sudo deploy_admin

# Copy SSH authorized_keys to new user
rsync --archive --chown=deploy_admin:deploy_admin ~/.ssh /home/deploy_admin/

Step 4: SSH Daemon Hardening

Create a security override config file to disable root login and password authentication:

sudo nano /etc/ssh/sshd_config.d/99-security.conf
PermitRootLogin no
PasswordAuthentication no
PubkeyAuthentication yes
MaxAuthTries 4
X11Forwarding no
sudo systemctl restart ssh

Step 5: UFW Firewall Configuration

sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 22/tcp comment 'SSH'
sudo ufw allow 80/tcp comment 'HTTP (Cloudflare proxy)'
sudo ufw allow 443/tcp comment 'HTTPS (Cloudflare proxy)'
sudo ufw enable
sudo ufw status verbose

Step 6: Install Docker Engine & Docker Compose V2

# Install prerequisites
sudo apt update && sudo apt install -y ca-certificates curl

# Add Docker's official GPG key
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# Add Docker apt repository
echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] \
  https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "$VERSION_CODENAME") stable" \
  | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

# Add non-root user to docker group
sudo usermod -aG docker deploy_admin
newgrp docker

# Verify
docker --version && docker compose version

Step 7: Cloudflare DNS Configuration

In your Cloudflare dashboard for your domain:

  1. Add an A record: Name = @, Value = YOUR_VPS_IP, Proxy status = Proxied (orange cloud).
  2. Add a CNAME record: Name = www, Target = yourdomain.com, Proxied.
  3. Under SSL/TLS → Overview, select Full (Strict) mode.
  4. Enable Always Use HTTPS.

Step 8: Nginx Reverse Proxy Setup

sudo apt install -y nginx
sudo systemctl enable nginx

Create your first application site block:

sudo nano /etc/nginx/sites-available/yourdomain.com
server {
    listen 80;
    server_name yourdomain.com www.yourdomain.com;
    root /var/www/yourdomain;
    index index.html index.php;

    location / {
        try_files $uri $uri/ /index.php?$args;
    }

    location ~ \.php$ {
        include snippets/fastcgi-php.conf;
        fastcgi_pass unix:/run/php/php8.3-fpm.sock;
    }
}
sudo ln -s /etc/nginx/sites-available/yourdomain.com /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
